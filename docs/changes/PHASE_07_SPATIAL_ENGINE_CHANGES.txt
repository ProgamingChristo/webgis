SPATIAL TYPES:
Coordinate, BoundingBox, Point/Line/Polygon geometry, SpatialReference,
DistanceResult, NearbyQuery/Result, WalkingTimeResult, ServiceAreaRequest/Result,
dan RoutingRequest/Result. Object Coordinate memakai longitude/latitude;
GeoJSON memakai [longitude, latitude]. CRS canonical EPSG:4326.

SPATIAL SERVICES:
- DistanceService: delegasi perhitungan meter ke PostGIS geography.
- ProximityService: ST_DWithin untuk transport_node/umkm_profile.
- BBoxService: GiST-compatible bbox intersection untuk empat entity whitelist.
- WalkingTimeService: estimator distance/speed dengan label metode eksplisit.
- ServiceAreaService: fail-closed SPATIAL_NETWORK_NOT_READY.
- UnavailableRoutingEngine: fail-closed ROUTING_GRAPH_NOT_AVAILABLE.

SPATIAL REPOSITORIES:
SpatialRepository memakai static RPC whitelist, explicit column projections,
request-scoped Supabase client/JWT, parameterized RPC values, mapper existing,
dan RLS SECURITY INVOKER. Tidak ada raw SQL dari client.

DTO:
Response feature hanya memuat id, label, entity_type, GeoJSON geometry, dan
provenance allowlist. owner_id, metadata, validation internals, dan raw database
representation tidak dikembalikan.

MAPPER:
Mapper memisahkan row/DTO, memvalidasi distance finite non-negative, memberi
analysis_method/source/srid, dan menghitung returned_count dari result aman.

ERRORS:
Ditambahkan controlled error codes untuk configuration, coordinate, distance,
geometry, bbox, radius, entity, query, network, request size, dan routing graph.
Response memakai canonical public message tanpa stack/PostgREST/SQL detail.

API ENDPOINTS:
- POST /api/spatial/distance
- GET /api/spatial/nearby
- GET /api/spatial/bbox
Semua wajib Bearer authentication, request_id, no-store response, structured
logging, strict Zod validation, entity/result/radius cap, dan rate-limit hook.
