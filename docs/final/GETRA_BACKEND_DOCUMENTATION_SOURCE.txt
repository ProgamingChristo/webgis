1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
GETRA Backend is a high-performance geospatial and transit intelligence backend
built on Next.js 16 (App Router) and Supabase (PostgreSQL with PostGIS). It provides
a resilient, contract-safe foundation for transit corridor management, study area
demarcation, transit stop mapping, local UMKM directories, and geodesic spatial
calculations. The system implements strict Clean Architecture, stateless Supabase
JWT Bearer authentication, Row Level Security, granular rate limiting, CORS allowlisting,
and production-ready Docker containerization.

--------------------------------------------------------------------------------
2. GETRA BACKEND OVERVIEW
--------------------------------------------------------------------------------
- Primary Role: Core geospatial, transactional, and API gateway for GETRA clients.
- Status: Foundation Implemented & Audited.
- Production Ingestion: Awaiting verified production datasets and transit feeds.
- Security Principle: Zero trust on client input, strict parameterization, no raw SQL,
  and no hardcoded credentials or service-role exposure.

4. ARCHITECTURE
--------------------------------------------------------------------------------
Layered Pipeline:
  HTTP Request -> CORS Check -> Rate Limiter -> Request ID & Headers ->
  Bearer Auth Guard -> Role Authorization Guard -> Zod Validation ->
  Domain Service -> Repository -> Supabase Client -> PostgreSQL / PostGIS with RLS

MAPID Adapter Pipeline:
  External Source -> MapidClient (Timeout/Retry) -> MapidSchema Validator ->
  MapidNormalizer (WGS84 GeoJSON) -> MapidMapper -> ExternalDataService (Dry-run) ->
  ExternalRecordRepository (Batch Persistence & Provenance Tracking)

Spatial Engine Pipeline:
  API Route (/distance, /nearby, /bbox) -> Coordinate / Bounds Validation ->
  Spatial Services (Distance, Proximity, BBox, WalkingTime) -> SpatialRepository ->
  PostGIS Stored Functions (ST_DWithin, ST_Intersects, ST_Distance, make_wgs84_bbox)

6. AUTHENTICATION SYSTEM
--------------------------------------------------------------------------------
- Provider: Supabase Auth via stateless Bearer JWT tokens.
- Header: Authorization: Bearer <jwt_token> (max length 8192 characters).
- Registration: POST /api/auth/register (Public; accepts COMMUTER, UMKM, COMMUNITY).
- Public Registration Restriction: ADMIN role is rejected with HTTP 403.
- Login: POST /api/auth/login (Returns access_token, user ID, email, profile role).
- Me Endpoint: GET /api/auth/me (Returns user details and profile via user JWT).
- Logout: POST /api/auth/logout (Stateless acknowledgement; client purges token).

7. USER PROFILE & ROLES
--------------------------------------------------------------------------------
Roles:
1. COMMUTER: General commuter transit search and spatial query access.
2. UMKM: Merchant business profile owner.
3. COMMUNITY: Community representative and transit initiative reporter.
4. ADMIN: Platform administrator with full reference data management rights.

Role Authorization Matrix:
- /api/health: Public
- /api/auth/login: Public
- /api/auth/register: Public (Non-Admin only)
- /api/auth/logout: Authenticated (All Roles)
- /api/auth/me: Authenticated (All Roles)
- /api/profile (GET/PATCH): Authenticated (All Roles)
- /api/spatial/distance: Authenticated (All Roles)
- /api/spatial/nearby: Authenticated (All Roles)
- /api/spatial/bbox: Authenticated (All Roles)

Admin Provisioning Security:
The ADMIN role cannot be assigned during signup. Trigger handle_new_user() raises
ROLE_NOT_ALLOWED if role = 'ADMIN' is found in metadata. Admin roles must be assigned
via direct SQL migration by database administrators.

--------------------------------------------------------------------------------
8. ROW LEVEL SECURITY (RLS)
--------------------------------------------------------------------------------
RLS is active on all 6 tables:
- public.profiles: Users read/update own profile; Admins read/update all via private.is_admin().
- public.spatial_sources: Authenticated users read; Admins manage all.
- public.study_areas: Authenticated users read; Admins manage all.
- public.transport_corridors: Authenticated users read; Admins manage all.
- public.transport_nodes: Authenticated users read; Admins manage all.
- public.umkm_profiles: Owners read/insert/update own; Admins manage all.

Privilege Hardening:
- profiles update column grant restricted to (display_name, avatar_url).
- umkm_profiles insert column grant restricted to user fields.
- Trigger private.enforce_umkm_trusted_fields_update() blocks non-admin updates
  to ownership and provenance metadata.

10. DATABASE ARCHITECTURE
--------------------------------------------------------------------------------
Tables (6 tables total):
1. profiles (id UUID PK FK auth.users, display_name, avatar_url, role, timestamps)
2. spatial_sources (id UUID PK, source_name, source_type, description, metadata, timestamps)
3. study_areas (id UUID PK, source_id FK, name, description, geometry MultiPolygon 4326, lineage, timestamps)
4. transport_corridors (id UUID PK, source_id FK, name, transport_mode, description, geometry MultiLineString 4326, lineage, timestamps)
5. transport_nodes (id UUID PK, source_id FK, corridor_id FK, name, node_type, transport_mode, geometry Point 4326, lineage, timestamps)
6. umkm_profiles (id UUID PK, owner_id FK profiles, source_id FK, business_name, category, description, address, geometry Point 4326, lineage, timestamps)

Foreign Key Deletion Rules:
- profiles.id -> auth.users.id ON DELETE CASCADE
- umkm_profiles.owner_id -> profiles.id ON DELETE RESTRICT
- All source_id references -> spatial_sources.id ON DELETE SET NULL
- transport_nodes.corridor_id -> transport_corridors.id ON DELETE SET NULL

17. PUBLIC API SECURITY
--------------------------------------------------------------------------------
- CORS: Strict allowlist against FRONTEND_ALLOWED_ORIGINS. Preflight OPTIONS on all routes.
- Rate Limiting: In-memory fixed window per client/user (Auth: 5/min, API: 60/min,
  Mutation: 20/min, Spatial: 30/min).
- Request Body Stream Caps: Global 64KB, Auth 8KB, Profile/Spatial 4KB.
- Security Headers: CSP default-src 'none', X-Frame-Options DENY, X-Content-Type-Options nosniff,
  Referrer-Policy no-referrer, Permissions-Policy camera=(), microphone=(), geolocation=(), HSTS.
- No Service Role Leak: Server routes never use service-role key for public requests.
