03. Architecture
The platform is a monorepo with npm workspaces:
- frontend: Next.js application and MapLibre client experience.
- backend: Next.js API routes, Supabase access, integrations, repositories, and deterministic services.

Main flow:
User/Admin UI -> GETRA API -> repository/service layer -> Supabase/PostGIS/pgRouting and provider integrations -> safe DTO back to frontend.

Mission provider flow:
Admin UI -> GETRA Admin API -> existing MAPID Mission ingestion services -> MAPID -> validation -> normalization -> idempotent persistence -> safe sync result.

05. Permanent Product Rules
- GIS computes. AI interprets.
- USER and ADMIN are the only canonical auth roles.
- Stakeholder modes are UX modes, not authorization roles.
- One real-world place should become one user-facing canonical merchant.
- Premium and Menu Go can enrich one canonical merchant; do not reintroduce duplicate pins.
- Property observation is not live property availability.
- Struk Go is transaction observation, not revenue proof.
- Activity evidence is contextual/accessibility evidence, not a direct routing-cost modifier.

19. Location State Architecture
The current intended distinction:
- actualLocation: user's real/geolocation position.
- explorationLocation: current map/search context.
- routeOrigin: route start used by routing calculation; may be user location, explicit merchant, or manual point.
- routeDestination: selected destination merchant/feature for route.
- selectedFeature / selectedId: current selected UI feature/detail, not automatically route destination.
- cameraState / cameraOwner: map camera control ownership; data updates should not own camera after user interaction.

Do not collapse these into one selectedLocation.
