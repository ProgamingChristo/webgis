UMKM INTELLIGENCE & ADVERTISING TRACK — PHASE 06
CAMPAIGN LIFECYCLE API CONTRACT & ENDPOINTS
================================================================================

1. OVERVIEW
--------------------------------------------------------------------------------
Phase 6 introduces dedicated endpoints for reading campaign lifecycle state,
updating schedules, and executing state transitions (pause, resume, cancel).
All endpoints enforce:
- Bearer JWT authentication (`Authorization: Bearer <token>`)
- Merchant ownership header (`x-getra-merchant-id: <merchant_uuid>`)
- Preflight CORS validation registered in `backend/src/lib/api-security/endpoint-policy.ts`


2. ENDPOINTS SPECIFICATION
--------------------------------------------------------------------------------

2.1. GET /api/umkm/advertising/campaigns/:id/lifecycle
------------------------------------------------------
Purpose: Retrieve full lifecycle state, readiness analysis, schedule, and allowed actions.
Headers:
  - `Authorization`: `Bearer <token>`
  - `x-getra-merchant-id`: `<merchant_uuid>`

Response (200 OK):
```json
{
  "request_id": "req-12345",
  "data": {
    "campaignId": "11111111-2222-3333-4444-555555555555",
    "merchantId": "aaaa1111-bb22-cc33-dd44-ee5555555555",
    "name": "Promo Kopi Pagi",
    "status": "SCHEDULED",
    "effectiveStatus": "SCHEDULED",
    "startAt": "2026-09-01T08:00:00.000Z",
    "endAt": "2026-09-15T22:00:00.000Z",
    "readiness": {
      "ready": true,
      "checks": {
        "merchant": true,
        "creative": true,
        "targeting": true,
        "schedule": true
      },
      "blockers": []
    },
    "allowedActions": {
      "canEditSchedule": true,
      "canPause": true,
      "canResume": false,
      "canCancel": true
    }
  }
}
```

2.2. PUT /api/umkm/advertising/campaigns/:id/schedule
-----------------------------------------------------
Purpose: Update start and end timestamps for a campaign.
Headers:
  - `Authorization`: `Bearer <token>`
  - `x-getra-merchant-id`: `<merchant_uuid>`
  - `Content-Type`: `application/json`

Request Body:
```json
{
  "start_at": "2026-09-01T08:00:00.000Z",
  "end_at": "2026-09-15T22:00:00.000Z"
}
```

Validation Rules:
- `start_at` and `end_at` must be valid ISO 8601 strings.
- `end_at > start_at`.
- `end_at > now` (cannot end in past).
- `ACTIVE` campaigns cannot be modified without pausing first.

Response (200 OK): Returns updated `CampaignLifecycleDTO`.

2.3. POST /api/umkm/advertising/campaigns/:id/pause
---------------------------------------------------
Purpose: Pause an active or scheduled campaign.
Headers:
  - `Authorization`: `Bearer <token>`
  - `x-getra-merchant-id`: `<merchant_uuid>`

Response (200 OK): Returns updated `CampaignLifecycleDTO` with `status = "PAUSED"`.

2.4. POST /api/umkm/advertising/campaigns/:id/resume
----------------------------------------------------
Purpose: Resume a paused campaign back to its effective schedule state.
Headers:
  - `Authorization`: `Bearer <token>`
  - `x-getra-merchant-id`: `<merchant_uuid>`

Response (200 OK): Returns updated `CampaignLifecycleDTO` with `status = "SCHEDULED" | "ACTIVE" | "ENDED"`.

2.5. POST /api/umkm/advertising/campaigns/:id/cancel
----------------------------------------------------
Purpose: Irreversibly cancel a campaign.
Headers:
  - `Authorization`: `Bearer <token>`
  - `x-getra-merchant-id`: `<merchant_uuid>`

Response (200 OK): Returns updated `CampaignLifecycleDTO` with `status = "CANCELLED"`.
