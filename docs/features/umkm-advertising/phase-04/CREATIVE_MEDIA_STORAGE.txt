# CREATIVE MEDIA STORAGE (PHASE 4)

## Bucket
- **Name**: `advertising-creatives`
- **Visibility**: Public (to allow easy map rendering of the assets by the client without complex signing workflows, since ads are meant to be seen).

## Path Structure
- `merchant/[merchant-id]/campaign/[campaign-id]/creative/[creative-id]/[timestamp]-[filename]`
- The path is generated by the server. The filename is sanitized.

## File Validation
- **MIME Types**: `image/jpeg`, `image/png`, `image/webp`.
- **Max Size**: 5MB
- **SVG / HTML**: Rejected to prevent active payload XSS.

## Upload Flow
- Uploads happen via our own backend `POST .../media` endpoint.
- We do not allow direct-to-storage uploads from the browser because Supabase Storage RLS policies become complex when validating `ad_creatives -> ad_campaigns -> merchants` relationships.
- The backend verifies eligibility and campaign ownership before using the Supabase client to upload.

## Orphan Files
- Old images are NOT automatically deleted in Phase 4 MVP when replaced, to keep the MVP simple. This will be addressed in future storage cleanup tasks.
