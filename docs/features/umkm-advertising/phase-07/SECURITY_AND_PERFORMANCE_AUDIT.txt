PHASE 07 — SPONSORED PIN & AD SERVING ENGINE
SECURITY AND PERFORMANCE AUDIT
================================================================================

1. SECURITY AUDIT
--------------------------------------------------------------------------------
- Endpoint Policy:
  * `GET /api/advertising/placements/sponsored-pins`: AUTHENTICATED with AUTH_HEADERS, rateLimit: "api".
  * `POST /api/umkm/advertising/campaigns/[id]/serving-preview`: AUTHENTICATED with AUTH_MERCHANT_HEADERS, rateLimit: "mutation".
- Tenant Isolation:
  * Owner preview strictly verifies `campaign.merchant_id === requested_merchant_id`.
- Data Sanitization:
  * Public DTO strips all financial, creator, and internal state fields.
  * Server enforces `label: "Sponsored"` and `sponsored: true`.
- Zero Event Side Effect Rule:
  * No database writes occur during ad serving candidate queries or previews.

2. PERFORMANCE & SCALABILITY
--------------------------------------------------------------------------------
- Spatial Indexes:
  * PostGIS index `idx_ad_campaign_targets_center_geom` utilized for radius centers.
  * Spatial index on `study_areas.geom` utilized for polygon containment.
- Fast Pre-filtering:
  * Campaigns filtered by `status NOT IN ('CANCELLED', 'ENDED')` before detailed pillar checks.
- Bounded Response Limit:
  * Client limit is clamped to [1..20] (default 5).
- Non-blocking Ray-Casting PIP:
  * Polygon containment evaluated in sub-millisecond execution time.
- Cache-Control:
  * Serving responses set `Cache-Control: no-store` to ensure real-time temporal accuracy.
