GETRA BACKEND + VALHALLA - DOCKER USAGE
========================================

Tanggal pembaruan: 2026-08-31 (Asia/Jakarta)

ARSITEKTUR
----------
Production menggunakan satu stack Docker Compose di VPS:

  reverse proxy HTTPS -> getra-backend:3000 -> valhalla:8002

Frontend tetap dibangun di Vercel. Database tetap Supabase remote. Compose tidak
membuat PostgreSQL dan routing tidak memakai Google Maps API.

PORT DAN NETWORK
----------------
Secara default port host hanya terikat ke loopback:

  127.0.0.1:3002 -> getra-backend:3000
  127.0.0.1:8002 -> valhalla:8002

Backend memanggil `http://valhalla:8002` melalui network Compose. Jangan membuka
port 8002 ke internet. Di production, port 3002 juga harus tetap tertutup dari
internet dan hanya diteruskan oleh Nginx/Caddy/reverse proxy HTTPS pada host.

ENVIRONMENT
-----------
Gunakan root `.env.local` yang di-ignore Git sebagai sumber interpolasi Compose.
Jangan menaruh secret di Dockerfile, build argument, Compose YAML, atau Git.

Required backend application configuration:

  NEXT_PUBLIC_SUPABASE_URL
  NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
  APP_ENV=production
  APP_BASE_URL=<origin API HTTPS resmi>
  FRONTEND_ALLOWED_ORIGINS=<origin frontend Vercel yang eksak>
  GETRA_BIND_ADDRESS=127.0.0.1
  GETRA_DOCKER_PORT=3002
  VALHALLA_BIND_ADDRESS=127.0.0.1

Set `TRUST_PROXY=true` hanya bila reverse proxy tepercaya menimpa forwarded
headers dan akses langsung ke backend diblokir. Secret feature-specific seperti
`SUB2API_API_KEY`, `MIDTRANS_SERVER_KEY`, dan Supabase privileged key tetap hanya
berada pada host/container backend. Jangan memakai prefix `NEXT_PUBLIC_` untuk
secret.

ROUTING DATA
------------
`routing-data/jabodetabek.osm.pbf` wajib tersedia dan berukuran masuk akal.
Jalankan `npm run routing:validate` sebelum start. File PBF, graph tiles, config,
dan arsip Valhalla adalah runtime artifact besar yang di-ignore Git.

Perbarui PBF secara terjadwal dari sumber OSM tepercaya, catat tanggal extract,
dan gunakan `VALHALLA_FORCE_REBUILD=True` hanya pada start pertama setelah PBF
diganti. Kembalikan ke `False` untuk restart rutin.

PRODUCTION COMMANDS
-------------------
Validasi tanpa mencetak environment yang sudah diekspansi:

  npm run docker:prod:config

Build dan start backend plus Valhalla, lalu tunggu keduanya healthy:

  npm run docker:prod:start

Observability dan stop:

  npm run docker:prod:status
  npm run docker:prod:logs
  npm run docker:prod:stop

Start pertama dapat memerlukan hingga puluhan menit karena Valhalla membangun
graph. Script menunggu maksimal 40 menit. Jangan menganggap stack siap hanya
karena process berstatus `Up`; kedua service harus `healthy`.

LOCAL DEVELOPMENT
-----------------
`npm run dev` tetap merupakan jalur hot reload. Untuk backend development pada
host ditambah Valhalla container, start service Valhalla dari overlay routing dan
set `ROUTING_BASE_URL=http://127.0.0.1:8002` di `backend/.env.local`.

Untuk menjalankan backend production artifact dan Valhalla secara lokal:

  npm run routing:start

Host binding default tetap loopback. Override `GETRA_BIND_ADDRESS` atau
`VALHALLA_BIND_ADDRESS` hanya bila kebutuhan network sudah ditinjau.

HEALTH DAN SMOKE
----------------
Backend readiness:

  curl.exe -i http://127.0.0.1:3002/api/health

Valhalla readiness:

  curl.exe -i http://127.0.0.1:8002/status

Backend health mencakup konektivitas Supabase. Valhalla health memeriksa endpoint
status provider. HTTP 503/unhealthy harus diselesaikan sebelum traffic dialihkan.
Routing failure harus menghasilkan state unavailable/no-route terkontrol, bukan
garis lurus atau estimasi yang dibuat-buat.

IMAGE SECURITY
--------------
- Multi-stage image, runtime Next.js standalone.
- Valhalla 3.8.3 memakai multi-architecture manifest digest yang dipin.
- Runtime user `node`, bukan root.
- `no-new-privileges` dan seluruh Linux capabilities dibuang pada override prod.
- Environment dan documentation tidak masuk build context.
- Graceful stop backend 30 detik dan Valhalla 60 detik.
- Reverse proxy direkomendasikan oleh panduan self-hosting Next.js dan wajib untuk
  topology production GETRA ini.

Production deployment aktual, DNS/TLS, firewall, graph build, image inspection,
dan hosted smoke test hanya boleh disebut PASS setelah dijalankan pada VPS target.
Lihat juga docs/VERCEL_DEPLOYMENT.md, docs/DEPLOYMENT_RUNBOOK.md, dan
docs/ROUTING_NAVIGATION.md.
